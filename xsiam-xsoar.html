CQL

Cortex Query Language

CQL is how we interrogate the XSIAM data lake, every endpoint, identity, firewall and cloud log in one pipe‑and‑stage grammar. We start every engagement by hunting, not alerting.

dataset xdr_data stage filter · comp · fields scope 90-day retention
hunt-encoded-powershell.cql XSIAM 
// Office app spawning encoded PowerShell, classic initial access
dataset = xdr_data
| filter event_type = ENUM.PROCESS
| filter action_process_image_name = "powershell.exe"
| filter action_process_image_command_line contains "-enc"
| filter causality_actor_process_image_name in ("winword.exe", "excel.exe")
| fields _time, agent_hostname, actor_effective_username, action_process_image_command_line
| sort desc _time
| limit 100
detect-c2-beaconing.cql XSIAM 
// Low-jitter periodic callbacks = likely C2 beacon
dataset = xdr_data
| filter event_type = ENUM.NETWORK and action_remote_port not in (80, 443)
| comp count() as hits, stddev(_time) as jitter by agent_hostname, action_remote_ip
| filter hits > 50 and jitter < 1500
| sort asc jitter
Correlation

Correlation Rules

A correlation rule is a CQL query on a schedule that promotes a finding into an alert, mapped to MITRE ATT&CK and a severity. This is where hunting becomes a tireless detection that runs every ten minutes.

output alert schedule cron maps to ATT&CK
impossible-travel.correlation XSIAM 
# Generates a HIGH alert on concurrent logins from 2+ countries
[rule]     name          = "Impossible Travel - SSO"
          search_window = 1h
          schedule      = "*/10 * * * *"

[query]
dataset = okta_sso_raw
| filter eventtype = "user.session.start" and outcome = "SUCCESS"
| comp count_distinct(country) as geos by actor_alternateid
| filter geos > 1

[mapping] severity = HIGH · tactic = "Initial Access" · technique = "T1078"
severity HIGH T1078 Valid Accounts window 1h dedup by actor
privilege-escalation.correlation XSIAM 
# Non-privileged account added to Domain Admins (Event 4728)
[query]
dataset = xdr_data
| filter event_type = ENUM.AUDIT and action_evtlog_event_id = 4728
| filter action_group_name = "Domain Admins"
| join (dataset = hr_directory) as h h.user = actor_effective_username
| filter h.is_privileged = false

[mapping] severity = CRITICAL · category = "Privilege Escalation" · technique = "T1098"
XSOAR

Playbooks & Commands

When an alert fires, XSOAR takes the wheel. Playbooks call integration commands with !verbs and Python automations, enriching, deciding and containing before an analyst even opens the ticket.

trigger→ enrich→ verdict→ contain→ close
phishing-triage.playbook XSOAR 
# War Room, phishing triage, command by command
!ip ip=${Email.SenderIP} using-brand="VirusTotal"
!url url=${Email.URLs} using-brand="URLScan"
!Set key=Verdict value=${DBotScore.Score}
!setIncident severity=3 owner="soc-tier2"
!ad-disable-account username=${Account.SamAccountName}
!closeInvestigation id=${incident.id} closeReason="Resolved - Malicious"
enrich-and-contain.py XSOAR · automation 
# Auto-contain a malicious indicator, no human in the loop
def main():
    ip = demisto.args().get("ip")
    res = demisto.executeCommand("ip", {"ip": ip})
    score = demisto.get(res[0]["EntryContext"], "DBotScore.Score")
    if score == 3:                       # malicious
        demisto.executeCommand("panorama-block-ip", {"ip": ip})
        demisto.executeCommand("setIncident", {"severity": 4})
    return_results(f"verdict={score}")

if __name__ in ("__main__", "builtins"):
    main()
