Operating model5 min read

Why AI, network and security keep failing as three separate programs.

Each one is run by a different leader, on a different budget, to a different metric. That’s the bug, not the org chart’s feature.

Walk into most enterprises and you’ll find three roadmaps that never touch: an AI program chasing models, a network program chasing uptime, and a security program chasing controls. Each is competent. Together they leave most of the value on the table, because the value lives precisely in the seams between them.

Where the value actually is

AI that can’t see network telemetry can’t run the network. Security that isn’t wired into the fabric can only react. A network with no intelligence is just pipes. The compounding outcomes, self-healing infrastructure, identity-aware everything, autonomous response, all sit at intersections that no single program owns. So no one builds them.

Siloed, the three compete for budget. Integrated, they compound. Same spend, different architecture of ownership.

The design that fixes it

  • One outcome, not three roadmaps. Fund a shared outcome, “an intelligent, self-defending network”, and let the three disciplines deliver against it together.
  • Shared telemetry as the spine. One observability layer everyone draws from. Data is the connective tissue; fragment it and you re-create the silos.
  • Platform thinking. Treat AI, connectivity and trust as one platform with internal customers, not three cost centres defending turf.
  • Accountability at the seams. Give someone explicit ownership of the intersections, with the authority to make trade-offs across all three.

You don’t need a reorg to start. You need one shared objective, one shared data layer, and one person accountable for the space between the teams.

Why now

AI is what forces the issue. The moment intelligence starts operating the network and informing security, the boundaries between the three become friction you can measure, in latency, in incidents, in stalled initiatives. The organisations that redraw those boundaries first won’t just save money. They’ll be able to do things their competitors’ org charts simply don’t allow.
